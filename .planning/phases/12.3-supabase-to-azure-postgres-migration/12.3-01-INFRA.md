# Phase 12.3 Plan 01 — Infrastructure Evidence

**Executed:** 2026-08-01
**Server:** `propulsar-db` (Azure Database for PostgreSQL Flexible Server, `propulsar-production` resource group)

## 1. Database created

```bash
az postgres flexible-server db create \
  --resource-group propulsar-production \
  --server-name propulsar-db \
  --database-name content_engine
```

Result: `content_engine` database created (UTF8 charset, en_US.utf8 collation).

Verified via `az postgres flexible-server db list -g propulsar-production -s propulsar-db -o table` — `content_engine` listed alongside the server's other existing databases (`n8n`, `propulsar_crm`, `chatwoot_production`, `voiceagent`, `soporte`, `relevamiento`, and the untouched legacy `supabase` database).

## 2. DDL as executed

`az postgres flexible-server execute` is not available in this environment (the `rdbms-connect` CLI extension fails to install here — pip/setuptools backend error in the Azure CLI's embedded Python interpreter — and no `psql` binary is present). **Deviation (Rule 3 - Blocking):** used the project's own `pg` npm package (already present in `node_modules`, same driver n8n's Postgres node uses) via a one-off Node.js script run through the temporary firewall rule, with `ssl: { rejectUnauthorized: false }` mirroring n8n's own `DB_POSTGRESDB_SSL_REJECT_UNAUTHORIZED=false` setting for this exact server. Same connection params (host/user/db/port/sslmode) as the plan specified — only the client tool differed.

## 4. Temporary firewall rule — created and deleted
