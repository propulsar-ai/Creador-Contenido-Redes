<task type="auto">
  <name>Task 1: Create content_engine database + content_sessions table + round-trip test</name>
  <files>.planning/phases/12.3-supabase-to-azure-postgres-migration/12.3-01-INFRA.md</files>
  <action>
1. Create the database (control-plane ARM call, no network access needed):
   ```bash
   az postgres flexible-server db create \
     --resource-group propulsar-production \
     --server-name propulsar-db \
     --database-name content_engine
   ```

2. To run DDL you need data-plane access. Install the connect extension if missing (`az extension add --name rdbms-connect --only-show-errors`), then open a TEMPORARY firewall rule for this machine's public IP:
   ```bash
   MYIP=$(curl -s ifconfig.me)
   az postgres flexible-server firewall-rule create \
     -g propulsar-production --name propulsar-db \
     --rule-name temp-ddl-12-3 --start-ip-address $MYIP --end-ip-address $MYIP
   ```
   Fetch the admin password (this is the same login n8n's own core DB connection uses on this Container App):
   ```bash
   PGPW=$(az keyvault secret show --vault-name propulsar-prod-kv --name db-postgresdb-password --query value -o tsv)
   ```

3. Execute this exact DDL via `az postgres flexible-server execute -n propulsar-db -u propulsaradmin -p "$PGPW" -d content_engine -q "..."` (or psql if the extension misbehaves — same connection params, `sslmode=require`):
   ```sql
   CREATE TABLE content_sessions (
     id                 UUID PRIMARY KEY DEFAULT gen_random_uuid(),
     session_id         TEXT UNIQUE NOT NULL,
     topic              TEXT,
     type               TEXT,
     angle              TEXT,
     platforms          TEXT[],
     image_model        TEXT,
     image_url          TEXT,
     final_image_url    TEXT,
     image_urls         TEXT[],
     format             TEXT,
     aspect_ratio       TEXT,
     story_expires_at   TIMESTAMPTZ,
     instagram_caption  TEXT,
     facebook_caption   TEXT,
     approval_number    TEXT,
     status             TEXT DEFAULT 'pending',
     publish_at         TEXT,
     created_at         TIMESTAMPTZ DEFAULT now(),
     updated_at         TIMESTAMPTZ DEFAULT now()
   );
   ```
   Design notes (from 12.3-RESEARCH.md, do not "improve"):
   - `publish_at` is TEXT on purpose (holds literal 'now' or an ISO string; read back and passed to `new Date(pub)` in 🕐 Compute wait_seconds). Do NOT make it TIMESTAMPTZ.
   - `platforms`/`image_urls` are TEXT[] on purpose (pg driver serializes JS arrays natively; JSONB would need ::jsonb casts + JSON.stringify in n8n expressions).
   - `num_images` deliberately excluded (no live node writes or reads it; carousel recomputes from imageUrls.length).

4. Synthetic round-trip test (proves the schema accepts everything the 3 INSERT nodes will send, and the recovery SELECT shape works):
   - INSERT a test row exercising ALL columns: `session_id='propulsar_test_12_3'`, `approval_number='0000000000'`, arrays for platforms (`ARRAY['instagram','facebook']`) and image_urls, `format='story'`, `aspect_ratio='9:16'`, `story_expires_at=now() + interval '24 hours'`, `publish_at='now'`, `status='pending'` — with `RETURNING *`.
   - SELECT with the exact recovery-read shape: `SELECT * FROM content_sessions WHERE approval_number = '0000000000' AND status = 'pending' ORDER BY created_at DESC LIMIT 1;` — must return exactly 1 row.
   - DELETE the test row and confirm 0 rows remain.

5. ALWAYS delete the temp firewall rule (even if a prior step failed):
   ```bash
   az postgres flexible-server firewall-rule delete \
     -g propulsar-production --name propulsar-db --rule-name temp-ddl-12-3 --yes
   ```

6. Write `.planning/phases/12.3-supabase-to-azure-postgres-migration/12.3-01-INFRA.md` recording: DDL as executed, round-trip test results, firewall rule created+deleted confirmation. (Credential id gets appended by Task 2.) NEVER include the password.
  </action>

Round-trip test output shows 1 row returned by the recovery-shaped SELECT and 0 rows after DELETE. `az postgres flexible-server firewall-rule list -g propulsar-production --name propulsar-db -o table` does NOT show `temp-ddl-12-3`.
  </verify>
