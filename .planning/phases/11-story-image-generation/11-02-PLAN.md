```bash
export $(grep -E '^(N8N_API_URL|N8N_API_KEY)=' .env | xargs)

# Find the workflow — name is typically "Propulsar Content Engine" or similar
WF_ID=$(curl -sS -H "X-N8N-API-KEY: $N8N_API_KEY" "$N8N_API_URL/workflows" | node -e "const w = JSON.parse(require('fs').readFileSync(0)); console.log(w.data.find(x => /propulsar|content|engine/i.test(x.name)).id);")
echo "Target workflow ID: $WF_ID"

# Fetch current version for diff-check only (NOT used for deploy)
curl -sS -H "X-N8N-API-KEY: $N8N_API_KEY" "$N8N_API_URL/workflows/$WF_ID" > /tmp/n8n-remote-before.json
node -e "const w = JSON.parse(require('fs').readFileSync('/tmp/n8n-remote-before.json')); console.log('Remote nodes (before):', w.nodes.length);"

# Build the update payload from local workflow.json
# n8n PUT expects { name, nodes, connections, settings, ... } — strip top-level metadata that n8n computes (id, active, createdAt, updatedAt)
node -e "
const local = JSON.parse(require('fs').readFileSync('n8n/workflow.json','utf8'));
const remote = JSON.parse(require('fs').readFileSync('/tmp/n8n-remote-before.json'));
const payload = {
  name: remote.name,
  nodes: local.nodes,
  connections: local.connections,
  settings: remote.settings || local.settings || {},
  staticData: remote.staticData || null
};
require('fs').writeFileSync('/tmp/n8n-deploy-payload.json', JSON.stringify(payload));
console.log('Payload nodes:', payload.nodes.length);
"

# PUT (deploy)
curl -sS -X PUT -H "X-N8N-API-KEY: $N8N_API_KEY" -H "Content-Type: application/json" \
  --data @/tmp/n8n-deploy-payload.json \
  "$N8N_API_URL/workflows/$WF_ID" | node -e "const r = JSON.parse(require('fs').readFileSync(0)); console.log('Deployed. Node count:', r.nodes?.length || r.data?.nodes?.length);"

# Activate
curl -sS -X POST -H "X-N8N-API-KEY: $N8N_API_KEY" \
  "$N8N_API_URL/workflows/$WF_ID/activate" | node -e "const r = JSON.parse(require('fs').readFileSync(0)); console.log('Active:', r.active || r.data?.active);"
```

**If n8n rejects the PUT with 400:**
- Common cause: version mismatch. Read the error body. Often fixable by adding `versionId` from the remote workflow to the payload.
- If the error mentions a specific node or connection, check that node in local `workflow.json` for a syntax issue and fix in a new commit before re-deploying.

**If n8n-mcp tools require a different call shape:** use them first (they handle auth/encoding); fall back to the curl pattern only if mcp is unavailable.
