## Meta Graph API dry-run (Task 2) — BLOCKED, not OK

**Outcome:** Dry-run from Felix's dev IP returns code 9004 / 2207052 ("Only photo or video can be accepted as media type") for **all** tested URLs, including a control Wikipedia URL known to be a valid image. Token and scopes verified valid via `/debug_token` and GET `/{IG_ACCOUNT}` both return 200 with expected payload.

### Tests performed (all from Felix's dev machine IP)

| # | image_url source | body format | media_type | result |
|---|---|---|---|---|
| 1 | AFD + synthetic 1x1 PNG (69B) | form-urlencoded | implicit | 400 / 9004 |
| 2 | AFD + synthetic 1080×1080 solid-red PNG (4979B) | form-urlencoded | implicit | 400 / 9004 |
| 3 | AFD + Ideogram JPG 1080×1080 (330459B) from exec 2026-04-16 | form-urlencoded | implicit | 400 / 9004 |
| 4 | AFD + same JPG | form-urlencoded | `IMAGE` explicit | 400 / 9004 |
| 5 | AFD + synthetic PNG | **`application/json`** (matches workflow.json) | implicit | 400 / 9004 |
| 6 | **`upload.wikimedia.org`** control URL + JPG | form-urlencoded | implicit | 400 / 9004 |

Test 6 is the tell: Meta rejects a known-valid Wikipedia image URL with identical 9004 from my IP. **→ AFD is not the issue; Meta is rejecting the request source.**

### Supporting evidence — token + IG account both healthy

```

  → 200 {
      is_valid: true,

    }

GET https://graph.facebook.com/v22.0/17841480004109313?fields=id,username,media_count,profile_picture_url
  → 200 { id: 17841480004109313, username: propulsar_ai, media_count: 6, profile_picture_url: ... }
```

### Hypothesis

Meta applies stricter acceptance on POST `/{IG_ACCOUNT}/media` than on read endpoints. The n8n-azure production pipeline historically succeeds from the Container App egress IP in West Europe (Meta has observed it since Phase 4); Felix's dev IP has no such history. Meta may respond with a generic 9004 for unregistered request sources as an anti-abuse heuristic.

### Consequence for Plan 12.1-01 success criteria

The plan required Task 2 dry-run to pass as a "pre-deploy safety check" preventing a double-revert if Meta rejects AFD post-deploy. **This check is not executable from the dev IP** regardless of URL correctness.

### Decision taken

Per checkpoint dialog with Felix (2026-04-23 ~21:50 UTC): **proceed to Wave 2 (Plan 12.1-02) with the understanding that Wave 3 (Plan 12.1-03) E2E execs against n8n-azure production serve as the real validation gate.** If Wave 3 first exec returns 9004 for the AFD URL, revert Wave 2's workflow PUT to versionId `c13b5cb9` (Plan 12-02 closure state, Options D/B/E band-aid still in place). One revert, not two.

**Recorded decision in:** `12.1-01-SUMMARY.md` (Open Questions → "Task 2 dry-run limitation") and `STATE.md` (Phase 12.1 entry). Plan text not amended — this SMOKE.md archives the deviation.
