**Goal:** Crear el AFD profile, flipear el container a Blob-level anonymous-read, registrar el endpoint hostname, y setear `AZURE_CDN_HOST` en el env de n8n-azure (EasyPanel / App Service). Ninguna edición de código en este task.

Este task requiere acceso interactivo al Azure Portal (clicks en la UI) y al host de n8n-azure (EasyPanel o Azure App Service) para setear la env var. No hay CLI path más simple — el "Front Door and CDN" blade de Storage es un wizard portal-only que pre-completa el origin correctamente. Azure CLI `az afd` existe pero requiere más parámetros manuales que inviertan el tradeoff.

### Step 1: Crear AFD Standard profile

1. Abrir https://portal.azure.com → buscar "Storage accounts" → click `propulsarcontent`
2. Panel izquierdo: **Security + networking** → **Front Door and CDN**
3. Sección "New endpoint":
   - **Service type:** Azure Front Door
   - **Create new profile** → Profile name: `propulsar-content-afd`
   - **Endpoint name:** `propulsarcontent` (generará hostname tipo `propulsarcontent-<hash>.z01.azurefd.net`)
   - **Origin hostname:** `propulsarcontent.blob.core.windows.net` (auto-completado)
   - **Pricing tier:** **Standard** (NO Premium — $35/mo base fee vs $330/mo; Premium solo se necesita para Private Link que no aplica aquí)
   - **Caching:** ON — "Ignore query strings" (container flipeará a anonymous-read, así que no hay SAS que preservar)
   - **Compression:** ON (default OK)
   - **WAF:** OFF / "No WAF policy" — CRÍTICO: WAF activo puede bloquear Meta fetchers silently, re-creando el problema que queremos resolver (RESEARCH Pitfall 1)
   - **Private Link:** OFF (Premium-only, no aplica)
4. Click **Create**. Azure tarda ~5-10 min en propagar globalmente (AFD manda config a PoPs).
5. Una vez creado, ir a **All resources** → `propulsar-content-afd` → copiar el **Endpoint hostname** completo (ej. `propulsarcontent-e3h4gxcff8d3a5bk.z01.azurefd.net`). Registrar en notas para Task 2 + SUMMARY.

### Step 2: Flipear container ACL a Blob-level anonymous-read

Research Pitfall 2 recomienda Option A (anonymous-read) sobre Option B (AFD Rules Engine + SAS). Razones: (a) blob names son UUIDs — security por unguessability es estándar CDN; (b) elimina 3 moving parts (SAS env var, rules engine, cache-key config); (c) content es public-by-intent (se publica en IG/FB).

1. Azure Portal → Storage accounts → `propulsarcontent` → **Data storage** → **Containers**
2. Click `propulsarcontent` (el container, no confundir con el storage account que tiene el mismo nombre)
3. Menu "..." arriba a la derecha → **Change access level**
4. Select **Blob (anonymous read access for blobs only)** — NO "Container (anonymous read access for containers and blobs)" que es más amplio y expone list operations
5. Click **OK** y confirmar

**IMPORTANTE:** Si "AllowBlobPublicAccess" del Storage account está `false`, el flip falla con un error. En ese caso: Storage account → **Settings** → **Configuration** → "Allow Blob anonymous access" → **Enabled** → Save → reintentar el flip del container. Esto fue requerido explícitamente para Phase 4 REHOST-05 HEAD verify, así que debería estar Enabled ya; si no, Felix habilita.

### Step 3: Verificar que el container flip funcionó sin SAS

Desde cualquier máquina (Windows git bash, Linux shell, lo que sea — NO desde adentro de Azure):

```bash
# Elegir un blob existente del container para probar (cualquier exec previa dejó blobs con UUIDs).
# Si no tenés uno a mano, tomar el blob_url de la última exec de Phase 12-02 (ver 12-02-SUMMARY.md).
# Si no, listar blobs: az storage blob list --account-name propulsarcontent --container-name propulsarcontent
#                     --auth-mode login --output tsv --query '[].name' | head -1

EXISTING_BLOB="2026/04/23/<uuid>.png"  # reemplazar con un path real

# Test SIN SAS (debe devolver 200 post-flip)
curl -I "https://propulsarcontent.blob.core.windows.net/propulsarcontent/$EXISTING_BLOB"
# Esperado: HTTP/1.1 200 OK | Content-Type: image/png | Content-Length > 0
# Si 404: el blob path está mal — probar otro.
# Si 403 "PublicAccessNotPermitted": el flip a Blob-level NO se aplicó O AllowBlobPublicAccess=false. Re-verificar Step 2 antes de continuar.
```

### Step 4: Smoke test contra el AFD endpoint

Con el AFD endpoint hostname registrado en Step 1 y confirmado el blob es anon-readable en Step 3:

```bash
AFD_HOST="propulsarcontent-<hash>.z01.azurefd.net"  # reemplazar con el real de Step 1

# Smoke test 1: curl default UA
curl -v -I "https://$AFD_HOST/propulsarcontent/$EXISTING_BLOB" 2>&1 | tee /tmp/afd-smoke-default.log
# Esperado:
#   HTTP/2 200
#   content-type: image/png (o image/jpeg según el blob)
#   content-length: >0
#   x-cache: MISS (primer fetch) o HIT (si otra request ya pobló el PoP)
#   x-msedge-ref: <AFD PoP identifier>

# Smoke test 2: facebookexternalhit UA (simula Meta fetcher)
curl -v -I -A "facebookexternalhit/1.1" "https://$AFD_HOST/propulsarcontent/$EXISTING_BLOB" 2>&1 | tee /tmp/afd-smoke-fb.log
# Esperado: mismo HTTP/2 200 + mismos headers. Si devuelve 403/429/cualquier-no-200 → WAF o Bot Fight Mode activo. Re-verificar Step 1 #4 y deshabilitar.

# Smoke test 3: GET completo para confirmar bytes llegan (no solo headers)
curl -s -o /tmp/afd-image-bytes.bin -w "status=%{http_code} size=%{size_download} ctype=%{content_type}\n" \
  "https://$AFD_HOST/propulsarcontent/$EXISTING_BLOB"
# Esperado: status=200 size=<coincide con content-length del HEAD> ctype=image/png
file /tmp/afd-image-bytes.bin
# Esperado: "PNG image data, ..." (o "JPEG image data")
```

**Si cualquier smoke test devuelve no-200:** STOP y escalar — NO avanzar a Task 2 porque significa que AFD/container no están sirviendo correctamente y el Plan 12.1-02 deploy va a regresionar en producción cuando la workflow empiece a apuntar a AFD.

### Step 5: Setear AZURE_CDN_HOST en n8n-azure host env

El workflow consume `$env.AZURE_CDN_HOST` via expression en el REHOST-06 seam (Plan 12.1-02). La env var debe existir ANTES del deploy para que el fallback `cdnHost || rawBlobHost` devuelva el CDN path en la primera exec post-deploy.

Dependiendo del stack de hosting actual:
- **EasyPanel** (si n8n-azure corre en EasyPanel): proyecto n8n → Environment → Add `AZURE_CDN_HOST=propulsarcontent-<hash>.z01.azurefd.net` (sin `https://`, sin `/` trailing). Apply → restart container.
- **Azure App Service directo:** portal → App Service → Configuration → Application settings → New application setting: name `AZURE_CDN_HOST`, value same → Save → app restart automático.
