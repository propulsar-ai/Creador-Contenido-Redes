### Step 2: Editar `n8n/workflow.json` — revertir 5 Meta-facing nodes de Option D

**Two-tier architecture clarification (READ FIRST before editing):**

The revert list has TWO distinct tiers. Treating them the same causes confusion and bugs.

**Tier A — Direct HTTP jsonBody reverts (3 nodes).** These are HTTP request nodes that POST to Meta Graph API and include an `image_url`/`url` field in their `jsonBody` expression. Editing the jsonBody is what changes what Meta sees:

| Node ID | Line | Call type | Field to revert |
|---------|------|-----------|-----------------|
| `ig-create-container` | ~1190 | POST `/{IG}/media` (single-photo IG) | `image_url` |
| `fb-publish-photo` | ~1361 | POST `/{PAGE}/photos` (single-photo FB) | `url` |
| `ig-create-story-container` | ~1435 | POST `/{IG}/media` (IG Story) | `image_url` |

**Tier B — Code fan-out source swaps (2 nodes).** These are Code nodes that produce per-item output containing `$json.blob_url`. Downstream HTTP nodes (the actual "carousel child" HTTP nodes) consume `$json.blob_url` and POST to Meta. We swap the Code node's upstream data source but do NOT edit the downstream child HTTP nodes:

| Explode Code node (edited) | Line | Downstream child HTTP node (NOT edited) | Child line | Child jsonBody field reads |
|----------------------------|------|-----------------------------------------|------------|----------------------------|
| `ig-carousel-explode` | ~2192 | `ig-create-child-container` | ~2220 | `$json.blob_url` |
| `fb-carousel-explode` | ~2389 | `fb-upload-photo-unpublished` | ~2417 | `$json.blob_url` |

When the explode Code node swaps its source from `Prep Re-host Input.image_urls` (Ideogram raw) → `Merge Rehost Output.blob_urls` (AFD URLs), the per-item output's `blob_url` field automatically carries the AFD URL. The downstream child nodes' jsonBody field (`$json.blob_url`) is transparent to this swap — NO edit needed on the children.

**DO NOT add `fb-upload-photo-unpublished` or `ig-create-child-container` to the edit list.** They inherit through fan-out. Post-edit verification in Step 6 confirms their jsonBody still reads `$json.blob_url` unchanged.

### Step 4: Cleanup de `AZURE_SAS_PARAMS` — DEFER

Research Open Q #5 menciona que `AZURE_SAS_PARAMS` se usa en REHOST-03 PUT URL. Con el container anonymous-read, el SAS token NO se necesita para reads, pero sí para writes (PUT). - Recovery:
  1. `git revert <12.1-02-commit-2>` — reverts the 5-node edits in `n8n/workflow.json` (restores Option D band-aid: Meta calls use Ideogram/Flux direct URL again)
  2. Re-PUT the main workflow using the same API deploy pattern from this task (reuse the script with the reverted local file)
  3. KEEP subworkflow edit (`commit-1`) — the REHOST-06 rewrite is safe to leave. The `cdnHost || rawBlobHost` fallback only affects the hostname emitted in `blob_urls[0].url`; since the main workflow is now reverted to use `final_image_url` in Meta calls, whatever hostname `blob_urls[0].url` carries is only consumed by the Sheets log / cleanup paths (which work with either hostname).   4. Verify: re-run one exec of 12.1-03 Task 1 smoke path; confirm Meta returns 200 on IG Story create.
- Estimated recovery time: ~10 min (revert + re-PUT + 1 smoke exec).

**Scenario 2 — AFD itself breaks mid-exec (timeout, 503, regional outage)**:

- Symptoms: Meta fetcher returns 504/503/timeout; n8n intra-cloud fetches to `assert-fb-story-url` timeout.
- Recovery:
  1. `git revert <12.1-02-commit-1>` — reverts the REHOST-06 subworkflow edit (restores raw Blob hostname in `blob_urls[0].url`). This alone is NOT enough because Meta STILL BLOCKS the raw Blob hostname (the whole reason Options D/B/E exist).

  4. Verify: one IG Story exec succeeds (Options D still works independently of AFD availability).
- Estimated recovery time: ~15 min (2 reverts + re-PUT both + 1 smoke exec).

**Common misconception (do NOT do this):** "Just unset `AZURE_CDN_HOST` in the n8n-azure env and everything rolls back." WRONG. The `cdnHost || rawBlobHost` fallback in REHOST-06 only affects the hostname in `blob_urls[0].url`. It does NOT:
- Restore Option D (Meta calls reading `final_image_url`) — Tier A jsonBody edits are code, not env-driven
- Restore Option B source swap — Tier B Code node bodies are also code
- Make Meta accept raw Blob hostnames — Meta's 2026-04-17 domain block is server-side, not client-side

Unsetting the env var will degrade the system to "Meta calls with raw Blob URL → 9004 every exec" — a worse state than Options D/B/E.
