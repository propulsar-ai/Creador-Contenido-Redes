# Smoke test: Meta acepta URLs servidas desde el VPS Hostinger (EasyPanel)

**Fecha:** 2026-07-31
**Contexto:** Antes de comprometerse a migrar el re-host de imágenes a Cloudflare R2 (plan original
de `12.1-HANDOFF.md`), se evaluó una alternativa más barata: reusar el VPS Hostinger que Propulsar
ya paga y opera (mismo VPS que corre `n8n` + `evolution-api` en producción, gestionado vía
EasyPanel). Se hizo un test controlado antes de invertir en construir cualquiera de las dos rutas
completas.

## Método

1. Credenciales encontradas ya existentes (nada nuevo que crear):
   - `hostinger-api-key` en Key Vault `propulsar-prod-kv` → confirma VPS `srv1293188.hstgr.cloud`
     (IP `82.112.253.236`, Ubuntu 24.04 + EasyPanel, 4 vCPU/16GB/200GB).
   - `EASYPANEL_API_TOKEN` + `EASYPANEL_BASE_URL` en `propulsar-atiende/.env` (local, gitignoreado)
     — generado en una sesión previa de despliegue de esa demo.
2. Este EasyPanel tiene un **límite de plan de 3 proyectos** — `projects.createProject` para un
   proyecto nuevo aislado devolvió `400 "You are not allowed to create more projects"`. Se optó por
   agregar un servicio nuevo **dentro** de `propulsar-atiende-demo` (el proyecto de demo interno de
   Propulsar, no uno de los que sirven clientes en vivo) en lugar de `n8n` o `evolution-api`.
3. Servicio de test: `httpbin-cdn-test`, imagen Docker Hub `kennethreitz/httpbin` (sirve un PNG real
   dinámico en `/image/png`, sin necesidad de inyectar archivos ni shell access al host).
   - `services.app.createService` con el campo `"image"` en la creación **no persiste el source**
     (gotcha ya documentado en `deploy-vps-demo.md` — verificar siempre con `inspectService`). Hubo
     que llamar `services.app.updateSourceImage` por separado para que el campo `source.image`
     quedara realmente seteado.
   - Dominio expuesto vía el wildcard existente de esta instancia:
     `httpbin-cdn-test-propulsar-atiende-demo.bacu5y.easypanel.host` (sin tocar GoDaddy/DNS).
4. Verificación: `curl -I` a `/image/png` → `200 OK`, `Content-Type: image/png`, 8090 bytes.
5. Test real contra Meta Graph API — se creó un **container** (nunca se llamó `media_publish`, no
   se publicó nada):
   ```
   POST https://graph.facebook.com/v22.0/{INSTAGRAM_ACCOUNT_ID}/media
     image_url=https://httpbin-cdn-test-propulsar-atiende-demo.bacu5y.easypanel.host/image/png
     caption=Test CDN Hostinger - propulsar
     access_token={META_PAGE_TOKEN}
   → 200 {"id":"17889713163666804"}
   ```
6. Cleanup: `services.app.destroyService` sobre `httpbin-cdn-test` — verificado con
   `projects.inspectProject` que el servicio desapareció y los demás (`bot-core`,
   `client-dashboard`, `client-dashboard-web`, `control-plane`, `control-plane-web`, `n8n-demo`,
   `postgres`) quedaron intactos. El container de Meta sin publicar expira solo (no requiere
   limpieza — no se llamó `media_publish`, no hay post real).

## Resultado

**Meta acepta el hostname `*.bacu5y.easypanel.host` (Hostinger/EasyPanel)** — mismo patrón de
prueba que usó la sesión 12.1 para Azure Blob (rechazado, código 9004), Azure Front Door default y
custom domain (ambos rechazados, código 9004), e Ideogram directo (aceptado, control positivo).
Esta es la segunda fuente que Meta acepta, y **no requiere una cuenta nueva de Cloudflare**.

## Recomendación para Fase 12.2 (reemplaza el plan de Cloudflare R2 en `12.1-HANDOFF.md`)

En vez de migrar el re-host a Cloudflare R2, migrar a un servicio de storage/re-host propio sobre
este mismo VPS Hostinger (nuevo servicio EasyPanel dedicado — no `httpbin`, un servidor de archivos
real tipo `halverneus/static-file-server` o un endpoint mínimo propio con subida/borrado vía HTTP,
reemplazando el rol que hoy cumple Azure Blob + Sub-workflow "Re-host Images to Azure Blob"). Mismo
seam que el plan de R2 (Wave 2 de `12.1-HANDOFF.md`): reescribir REHOST-01 (subida) y el nodo de
limpieza (`🗑️ Delete Azure Blob` → DELETE contra este servicio), revertir los 5 nodos Meta-facing de
Options D de vuelta a la URL re-hosteada. **Diferencia clave vs Cloudflare:** no hace falta cuenta
nueva, ni token nuevo — ya existen `hostinger-api-key` y `EASYPANEL_API_TOKEN` — y no hace falta
tocar GoDaddy DNS (se puede usar el wildcard `bacu5y.easypanel.host` directo, igual que este test).

**Riesgo a vigilar:** este VPS tiene el plan EasyPanel limitado a 3 proyectos — el servicio nuevo de
producción debe ir dentro de un proyecto existente (recomendado: uno nuevo con nombre propio si el
límite lo permite tras liberar algo, o dentro de `propulsar-atiende-demo` igual que este test) y
nunca modificar los servicios ya presentes (`n8n`, `evolution-api`, `propulsar-atiende-demo/*`).
