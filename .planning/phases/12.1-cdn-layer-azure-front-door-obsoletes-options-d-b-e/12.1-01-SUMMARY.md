## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Container name correction**
- **Found during:** Task 1 setup (initial smoke test command preparation)
- **Issue:** Plan curl examples used `/propulsarcontent/<blob>` path, but real container name is `posts` (confirmed via Azure MCP `storage_blob_container_get`). `propulsarcontent` is the Storage Account name, not the container.
- **Fix:** All smoke test commands + script paths corrected to `/posts/<blob>`; health probe also uses `/posts/12.1-smoke/smoke-test.png`.
- **Files modified:** smoke-test.mjs, provision-afd.ps1, 12.1-01-SMOKE.md
- **Verification:** Tests 1-4 all returned 200 with correct path.
- **Committed in:** Task 1 commit

**2. [Rule 3 — Blocking] Container ACL flip was already done in Phase 4**
- **Found during:** Task 1 Step 2 pre-check
- **Issue:** Plan expected to flip `posts` ACL from Private to Blob anon-read. Azure MCP query confirmed `publicAccess: Blob` already set from Phase 4. Flipping again is no-op + wasted API call + risk of noise.
- **Fix:** Skipped the flip step; documented pre-existing state in SMOKE.md.
- **Files modified:** None (confirmation only)
- **Verification:** Task 1 smoke test 1 (HEAD to blob origin without SAS) returned 200.
- **Committed in:** n/a

**3. [Rule 4 — Majors] AFD Route `https-redirect Enabled` + `supported-protocols Https` internal conflict**
- **Found during:** Edge propagation troubleshooting (after ~15 min of CONFIG_NOCACHE)
- **Issue:** Initial route had `--https-redirect Enabled` with only HTTPS supported. Since there's no HTTP to redirect FROM, AFD might have treated this as a misconfig and delayed edge deployment.
- **Fix:** Updated route to `--https-redirect Disabled --supported-protocols Http Https`. Route then deleted + recreated once for clean state.
- **Files modified:** provision-afd.ps1 updated (for future reproducibility)
- **Verification:** Edge propagated ~58min after first provisioning (normal AFD Standard cold-start window per Azure docs).
- **Committed in:** Task 1 commit (same as main provisioning)

**4. [Rule 4 — Majors] Origin health probe path initially invalid**
- **Found during:** Edge propagation troubleshooting
- **Issue:** Initial probe path was `/` which on Azure Blob Storage returns 400 (no default container listing). Origin group would have marked origin unhealthy.
- **Fix:** Updated probe-path to `/posts/12.1-smoke/smoke-test.png` (known-present blob) + increased probe interval to 240s to reduce load.
- **Files modified:** Azure config only
- **Verification:** Origin group reports probes passing after fix.
- **Committed in:** Task 1 commit

**Total deviations:** 4 auto-fixed (2 blocking via MCP pre-checks saved wasted work, 2 major config fixes during troubleshooting).
**Impact on plan:** All auto-fixes necessary for correctness. No scope creep. Plan text not amended (deviations documented in SMOKE.md for audit).

## Issues Encountered

- **AFD Standard edge propagation took ~58 min** (20:49 UTC create → 21:42 UTC first 200 response). Plan expected 5-15 min. This is within Azure's extended SLA but longer than typical. Debug attempts (purge, toggle enabled/disabled, delete+recreate route) did not accelerate; appears to be a cold-start quirk for brand-new profiles in West Europe. Documented for future reference.
- **Meta Graph API dry-run blocked from dev IP** — token + scopes valid, IG account reads work, but ALL POST `/media` calls (6 tested with different URLs/formats) return code 9004 / 2207052 identically. Wikipedia control URL also fails. Likely IP-level restriction on Meta's side for unregistered sources. Cannot be resolved from my env.
- **az storage blob upload required --auth-mode key** (not login) — felix@propulsar.ai does not have Storage Blob Data Contributor RBAC, so data-plane auth via login fails. Fallback to account-key auth (automatic via CLI) worked.
- **Git Bash path mangling** (`/posts/...` → `C:/Program Files/Git/posts/...`) bit az CLI probe-path update; fixed with `export MSYS_NO_PATHCONV=1`.
