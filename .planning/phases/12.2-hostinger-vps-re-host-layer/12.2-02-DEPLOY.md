## Drift Discovery (important — read before future deploys)

Pre-deploy diffing (remote GET vs. the repo's last-known-good commit `505b52f`, the 12.1-02 rollback state) found the **main workflow had drifted out-of-band from this repo** on 4 nodes, unrelated to this plan's scope:

- `openai-text`, `openai-carousel` — migrated from the `n8n-nodes-langchain.openAi` node (credential `OpenAI-Propulsar` / `wWEhRsD5ilt2xGvz`) to a raw HTTP Request node hitting `https://propulsar-prod-aoai.openai.azure.com/...` with a `httpHeaderAuth` credential (`AOAI-ApiKey-Header`) — i.e. the Azure OpenAI migration referenced in MEMORY.md as "in progress, awaiting quota" appears to have **already landed directly in n8n**, without a corresponding repo commit.
- `parse-carousel`, `parse-content` — Code nodes updated in lockstep to read `$input.first().json.choices[0].message.content` (AOAI/OpenAI-chat-completions response shape) instead of `$input.first().json.message.content` (langchain node's response shape).

All other nodes, all connections, and settings were confirmed byte-identical between remote and the repo's `505b52f` commit (0 other diffs, 100% node-id parity, no missing/extra nodes).

**Why this mattered for this deploy:** a direct `PUT` of the local (stale) `n8n/workflow.json` would have **silently reverted the live AOAI migration** back to the old OpenAI-node shape — breaking text generation in production (wrong response-parsing shape) as a side effect of this plan's unrelated re-host work.

**Mitigation applied:** Task 3's main-workflow deploy used a **patch strategy** instead of a full-file PUT — fetched the current remote workflow as the base, and replaced *only* the 8 node ids this plan intentionally edited (`ig-create-container`, `fb-publish-photo`, `ig-create-story-container`, `ig-carousel-explode`, `fb-carousel-explode`, `extract-blob-names`, `delete-azure-blob`, `assert-fb-story-url`), leaving all 83 other remote nodes — including the drifted AOAI nodes — completely untouched. A post-deploy safety check explicitly asserted `openai-text`/`openai-carousel` still point at `openai.azure.com` (i.e. were NOT reverted).

**Follow-up needed (not in this plan's scope):** `n8n/workflow.json` in this repo is now stale for `openai-text`/`openai-carousel`/`parse-carousel`/`parse-content` — a future small sync commit should pull the live AOAI node shape back into the repo so the next plan's pre-deploy diff is clean again.
